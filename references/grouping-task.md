# 归组任务（S3）

你负责一个目录，把它内部的**单元**归成**组**。

## 任务

**组 = 去向相同的单元集合。**

不是"主题相似"，是"这些东西应该待在一起"。

```
同一门课的 34 集              → 1 组
同一部书的 4 种形态            → 1 组
同一批下载但主题不同的 3 个工作流 → 各 1 组
12 张内容无关的截图            → 各自 1 组，或归成"截图"1 组（看数量）
```

---

## 归组能发现的四类关系

**这是 S3 最核心的价值——单看一个目录永远发现不了。**

### 一、集数互补（最紧急）

```
同一部作品被拆成两个目录，编号正好互补
  目录 A：01-04, 07-08, 09-10, 11-12
  目录 B：05-06
→ 拼起来才是完整一季
```

**不合并的话，两半都是残的。** 这不是"整理问题"，是内容完整性问题。

识别方法：比对各目录的文件名前缀和编号，看是否有交集为空但编号连续的组合。

### 二、多季多版本

```
同 IP 的多个季度 / 多套 BD / 多个字幕组
→ 取超集，其余标注关系，不删
```

识别方法：作品名归一化后比对（去字幕组标签、去集数、去版本标记）。

**注意防误判**：名字像但不是一个作品的情况非常多。
```
『持续狩猎史莱姆三百年』≠『噗妮露是可爱史莱姆』≠『转生史莱姆』
『反派千金等级99』≠『中年大叔转生反派千金』
五个带「魔王」的分属五部不同作品
```

### 三、跨层重复

```
顶层与嵌套目录各一份
→ 比对后报告重复关系，不自动删除或覆盖任何一份
```

**必须比哈希，不能假设。** 实测中：
```
顶层 35.09GB / 嵌套 35.27GB   → 抓取时点不同，是两份
同名内外目录 40 文件全等       → 真重复
内层只有空子目录               → 外层不是壳，要看外层自己
```

### 四、形态类聚

```
来源/形态一致但作品各异
→ 只聚合，不合并内容
```

例：同一网站在线源的录屏散件、同一批下载的短剧、同一工具产出的截图。
它们互不相关，但放在一起比散着好找。

---

## 必须跨子目录

**一个目录的三个子目录可能只是三次搬运的产物，名字反映的是"什么时候搬来的"而不是"装了什么"。**

实测：某目录的三个子目录名是两个下载工具名加一个单字母，
实际内容是四类混装——按子目录分别归组，永远凑不出正确的组合。

**正确做法：把三个子目录的所有单元拉到一起，按内容重新归组。**

---

## 判据优先级

```
先按内容 id 判      workflow 根节点 id / 文件哈希 / 内部结构
再按元数据判        created / creator / 版本号
最后才按名字判      名字像但 id 不同的一律不并
```

### 实测教训

```
两个工作流文件名相似 → 根节点 id 不同 → 不是同一套
完整文件 SHA256 相同 → 字节重复；精度标签不同应核查标签或哈希对象。路径依赖不同仍可都保留。
11 个大 xlsx          → created 时间戳分 3 组 + creator 字段分 2 组 → 5 组
两个 tag 词库          → 11 个文件 MD5 全等，但各有独有内容 → 同组不同单元
```

## 猜想 → 验证 → 确认

**这一步不是可选的。** 你的判断会被下游直接使用，没有验证过程的结论
等于第一印象。

### 分三级，按情况写

| 级别 | 什么时候 | 怎么写 |
|---|---|---|
| **direct** | 结构信号本身即证据 | 一句结论 + `evidence`，不写三步 |
| **verify** | 名字有歧义、内容要看才明白 | `hypothesis` + `verification.method/findings` |
| **full** | 涉及边界、合并、名实冲突 | 完整三步，缺一不可 |

### direct 怎么写

```json
{
  "action": "keep",
  "evidence": ["steamapps/ 下有 appmanifest_*.acf，是 Steam 库根"],
  "confidence": "high"
}
```

**`evidence` 里那句就是验证**，只是不需要展开成三段。

### verify 怎么写

```json
{
  "hypothesis": "名字叫 Compressed，猜测是压缩包集合",
  "verification": {
    "method": "数类型分布 + 抽 3 个包读条目表",
    "findings": "确实是压缩包，但混着 ROM、游戏、工具、引擎数据"
  },
  "confidence": "medium"
}
```

### full 怎么写

```json
{
  "hypothesis": "这三个 rar 和那个目录是同一部剧",

  "verification": {
    "method": "读三个 rar 的条目表（不解压）：01-04 / 05-06 / 07-12",
    "findings": "三个 rar 集数正好互补，拼起来等于目录那份",
    "disproved": ["最初以为是三份重复，实际是分卷"]
  },

  "confirmation": {
    "holds": true,
    "confidence": "high",
    "why": "集数编号互补，不是重复",
    "residualRisk": "没比字节，可能有重新压制"
  }
}
```

### 验证的顺序：先本地，再外部

| 猜想 | 本地证据 | 要联网吗 |
|---|---|---|
| 这是成品音乐 | 里面是 .mp3 还是 .exe | 不要 |
| 这是一组分卷 | 卷号连不连续 | 不要 |
| 这是同一作品两份 | 文件数、体积、同名文件哈希 | 不要 |
| 这是安装包不是游戏 | exe + 数据目录 + 存档 | 不要 |
| 这是哪个作品 | 需要外部资料 | **要** |

**外网只在"需要知道作品叫什么"时才有用。** 前面这些全都不用联网，
本地一秒就能得到答案。

### 验证的核心：找能推翻自己的证据

顺着第一印象找证据，什么都能找到。

```
✗  "查到它是音乐软件"        → 归到音乐      （只找支持的证据）
✓  "查到它是合成引擎，声库是采样库，
     最初按名字归为音乐是错的"               （推翻过）
```

**`disproved` 这个字段就是逼你说明推翻过什么。**
从没推翻过任何东西的判断，往往是没真去验。

## 输入输出

**输入**：目录路径 + 已知的单元清单（`units_*.json`）

**输出**：

```json
{
  "path": "/path/to/dir",
  "total_units": 35,
  "groups": [
    {
      "name": "编程课程",
      "units": ["编程大礼包", "编程资料", "初等数论", "python"],
      "relation": "theme",
      "why": "都是学习材料，同一时期下载",
      "confidence": "high"
    },
    {
      "name": "失业魔王",
      "units": ["失业魔王\\", "[AniArchive] Shiye Mowang (05-06)"],
      "relation": "episode-complement",
      "why": "目录有 01-04/07-08/09-10/11-12，顶层那包正是缺的 05-06，拼起来才完整",
      "confidence": "high"
    }
  ],
  "solo_units": ["解压教程（必看）"],
  "uncertain": [
    {"unit": "F丨3", "why": "名字零信息，内容看不出归属"}
  ]
}
```

`relation` 字段标注关系类型：
```
theme               主题相同
episode-complement  集数互补
multi-version       多季多版本
cross-layer-dup     跨层重复
form-cluster        形态类聚
```

---

## 边界

- **只归组，不决定去向。** 不写"移到 /path/to/XXX"
- 组名用内容本身的名字，不用"其他""杂项"
- 拿不准的，单独列进 `uncertain`，不要硬塞
- 一个组至少 2 个单元；单个单元进 `solo_units`
- **不要为了"看起来整齐"而硬凑组**

## 硬约束

- 只读
- 路径用 `-LiteralPath` 或 Python `os.scandir`
- 不打开文件内容（除了必须读文件头的零信息名）
- 不递归超过 2 层
- **用汇总形式**：300 个游戏不要逐个列，用 `{"桶":"1","games":173}` 表示
- **发现疑似涉及未成年人的性内容**：停止该路径的一切操作，只记路径
